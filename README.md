# LH43QBCEBGCXKR_system

삼성 사이니지 **LH43QBCEBGCXKR (QB43C)** 세로 화면에 띄우는 정보판입니다.
재택근무 중 책상 옆에 두고 뉴스·날씨·버스를 훑어보려고 만들었습니다.

화면은 1080×1920 세로 고정이고, 언론사 8곳 + 날씨 + 버스 + 공지 카드가 자동으로 돌아갑니다.

---

## 어떻게 돌아가나

```
설정.json  →  수집기.py  →  콘텐츠/데이터.js  →  signage.html  →  사이니지
                  ↓
              콘텐츠/버스.json  (버스만 짧은 주기로 따로)
```

- **수집기.py** — RSS·공공데이터 API에서 값을 받아 파일로 적습니다. AI를 쓰지 않아 토큰 비용이 없습니다.
- **서버.py** — 화면 파일을 사이니지에 넘겨주고, 리모컨이 보내는 요청(`/bus-boost`)을 받습니다.
- **signage.html** — 화면 전부. 카드 전환·아코디언·하단 전광판이 모두 여기 있습니다.

## 쓰려면

### 1. 인증키 넣기

**인증키는 저장소에 두지 않습니다.** 옆에 `.env` 파일을 만들어 적습니다.

```
DATA_GO_KR_KEY=발급받은_키
```

[공공데이터포털](https://www.data.go.kr)에서 아래 네 가지를 신청하면 하나의 키로 모두 씁니다.

| 서비스 | 쓰는 곳 | 하루 한도 |
|:---|:---|---:|
| 기상청_단기예보 조회서비스 | 지금 기온·시간별 예보 | 10,000 |
| 기상청_중기예보 조회서비스 | 주간 6일 | 10,000 |
| 기상청_생활기상지수 조회서비스(4.0) | 자외선지수 | 10,000 |
| 한국환경공단_에어코리아_대기오염정보 | 미세·초미세 | 500 |
| 서울특별시_버스도착정보조회 서비스 | 버스 도착정보 | 1,000 |

`./API확인.command` 를 실행하면 어떤 것이 열려 있고 어떤 것이 대기 중인지 한 번에 보여줍니다.

### 2. 지역 바꾸기

`설정.json` 에서 고칩니다.

- **날씨** — 기상청 격자 좌표(`격자X`, `격자Y`). 서울 마포구 상암동은 `58, 127`
- **대기질** — 에어코리아 측정소 이름. 행정동이 아니라 **구 단위**입니다(`마포구`)
- **버스** — 정류장 표지판의 5자리 ARS 번호. `우선노선` 에 적은 노선이 맨 위에 고정됩니다

### 3. 켜기

```bash
./시작.command      # 수집기 + 서버를 함께 켭니다
```

사이니지에서 `http://<맥 IP>:8899/signage.html` 을 띄웁니다.

## 알아둘 점

**기사는 최신순이 아니라 언론사가 정한 순서를 따릅니다.** 피드가 하나면 그 순서 그대로(`편집순`), 여러 섹션이면 섹션마다 한 건씩 돌아가며 뽑습니다(`번갈아`). 한 섹션이 화면을 독점하지 않으면서도 언론사의 편집 의도를 살리기 위해서입니다.

**본문은 가져오지 않습니다.** 언론사 저작권 표시와 `robots.txt` 를 지켜 공개된 `og:description` 만 씁니다.

**사진은 흑백으로 줄여 저장합니다.** 이 기기는 사진 한 장 푸는 데 94ms가 걸려서, 표시 크기의 75%(756×525)로 줄이면 픽셀이 56%가 되어 그만큼 빨라집니다. 몇 미터 떨어져 보는 화면이라 화질 차이는 눈에 띄지 않습니다.

**API 호출량을 아낍니다.** 버스는 평소 5분 간격(하루 약 336건)이고, 리모컨으로 집중조회를 켜면 30분 동안 노선 하나만 10초마다 봅니다(1회 180건). 하루 한도 1,000건 안에서 세 번까지 쓸 수 있습니다.

## 이 기기에서 알아낸 것

- **MDC 프로토콜**은 TCP 1515, Display ID는 반드시 **1** (0이면 무응답)
- **URL Launcher** 는 앱(.wgt) 설치 통로이지 웹 뷰어가 아닙니다. 웹 주소를 넣으면 "앱을 다운로드할 수 없습니다"
- 네이버 등 대부분의 사이트는 `X-Frame-Options` 로 iframe 표시를 막습니다. 그래서 직접 위젯을 만들었습니다
- 성능 측정: 높이 애니메이션 229fps / 위치 이동 271fps — 렌더링은 문제없고 **사진 푸는 비용(장당 28ms)이 진짜 병목**이었습니다
